2025 to nowiFood · Remote

iFood

Senior Software Engineer · AI Platform / Backend

I'm the lead architect of an internal, white-label ML inference platform in Go. It ships as a Docker image that 10+ data science teams self-deploy on AWS EKS, each running their own instance. It sits between the apps and their already-served SageMaker endpoints. It doesn't serve the model; it runs everything around the call from a YAML config: per-request enrichment, schema validation at several stages, the model invocation, and response validation. The engine fans enrichment steps out in parallel (errgroup with sync.Cond for dependencies), with read-through caching, background credential refresh, and circuit breakers on every external call. On a high-traffic surface (50M+ users), one deployment handles 6,000+ requests a second, well under 100ms, and inside that budget each request runs nine parallel enrichments and three schema-validation stages. I extended it into an OpenAI-compatible gateway for our fine-tuned models, and shipped a LangGraph and Langfuse support agent over a RAG index that took the team's ticket load from three or four hours a day to about one. I'm also the person here who leans on coding agents the hardest, building the tooling and running the workshops for the rest of engineering.

More recently I've been building the V2 of BESH, our batch-inference platform for LCM (iFood's own generative model) and a dozen other internal LLMs. V1 shared inference across models; V2 is a distributed rewrite where every model gets its own set of workers and GPUs, so one noisy job can't starve another. It now runs 100M+ requests a week. I moved worker scaling onto KEDA so the fleet sits near zero between runs, and rebuilt GPU autoscaling after learning the obvious metric, KV-cache usage, doesn't actually predict load for this workload. The fix that mattered most was a backpressure loop that discovers how much a model can take instead of being told, built on the same idea as TCP congestion control. I also traced a full-fleet outage back to Kubernetes quietly evicting a warm pod mid-run, not our code, and closed that gap with disruption budgets and canary rollouts.

void

what it is

An infinite generative audiovisual canvas. You type a word, a small language model reads the moment and picks a mood, and Rust generates the art and the music from it. The browser only draws the geometry and sounds the notes. A hand-drawn creature wanders the screen, changes shape, and talks back.

system design

Rust does the heavy lifting. A Rust crate compiles to WebAssembly and generates everything deterministically from a seed: the visual templates (flow fields, boids, strange attractors, Julia and Mandelbrot sets) and the music (scale-locked, with real modal modulation). A Rust axum server runs the LLM creative director on a Groq free-tier budget, with a pressure-based fallback so it never goes over the limit and never goes silent. TypeScript stays a dumb renderer. The static front end lives on GitHub Pages, always on; the Rust backend runs on Render and only wakes to steer the mood. If it is cold or down, the front end falls back to a local heuristic, so the canvas is always alive.

playdoom: a RAM net learns Doom

open source live

A weightless RAM neural network, truth-table neurons with no backprop and no GPU, evolved by a genetic algorithm. I wrote it nine years ago to play tic-tac-toe, then dropped the same brain into Doom. The game's depth buffer becomes a grid of boolean sensors, the neurons vote on a move, and selection alone teaches it to run a corridor: over 25 generations 1 in 14 grows to 7 in 14 of the population clearing the gauntlet. The preview replays the fittest brain and streams the network's learning log underneath.

Laeleficator

open source demo

A fine-tuned Qwen2.5 model that rewrites innocent Brazilian Portuguese into phrases that carry lá ele, the reflexive double-entendre defence from Bahian slang. Parallel Claude subagents scrape, vet, pair, and adversarially judge every training pair, with zero manual review, then an agent research loop trains and evaluates one hyperparameter change at a time on MLX-LM, local on my M1 Max. Best result so far clears a strict three-judge panel on 17.6% of held-out cases. Still an open problem, not a shipped product.

Atlas Jiu-Jitsu

open source live

A knowledge graph for Brazilian jiu-jitsu. Each position is a node, and every sweep, submission, and guard pass is an edge, so you can see the whole game at once instead of watching one technique video at a time. I wrote a 400-line parser for GrappleMap's base62 skeletal format, then a small Three.js renderer that interpolates between joint poses with quaternion SLERP. The figures are real geometry, not pictures. Eleven validators run in the test suite and catch curation mistakes before they reach the live atlas.
