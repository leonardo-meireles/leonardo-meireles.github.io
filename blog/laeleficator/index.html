My model still doesn't get the joke

August 14, 2026 · 6 min read · the laeleficator project

In Brazil, when someone says something innocent that also carries a second, riskier meaning, whoever catches it says "lá ele": that's on you, not me. Laeleficator is a small language model I'm fine-tuning to rewrite plain sentences so they earn that reaction. Two months in, it mostly fails. This is the honest write-up, not the highlight reel.

what it's supposed to do

You give it a harmless sentence. It hands back a version that still reads as harmless on the surface, but that a Brazilian ear catches instantly. "Você faz vitamina? Me faz uma com mamão?" becomes "Você bate uma vitamina de mamão pra mim? 👀". Same request, same words in spirit, one small shift that changes what the sentence means. The gap between too explicit and too subtle is narrow, and that gap is the entire task.

an agent builds the dataset, I never touch it

Nobody hand-labels this data. A Claude Workflow runs five stages of subagents in sequence: scrape or seed candidate phrases, vet each one on three dimensions (is it actually a double entendre, does it read as natural Brazilian Portuguese, is it subtle enough), build the input/output pair, generate two or three context variants per pair, then run an adversarial multi-judge pass that drops anything where the output isn't clearly more charged than the input. What survives becomes data/final/dataset.jsonl, currently 199 curated pairs.

an agent runs the research loop too

Training is local: MLX-LM, LoRA, on my M1 Max, no cloud GPU. But I'm not hand-tuning hyperparameters either. I wrote a research program modeled on Karpathy's autoresearch idea: an agent proposes one change per iteration, either to the data, the base model, or a LoRA setting, trains, evaluates against a held-out set, and keeps the change only if the metric improves. Every run gets a row in a ledger, so the history is a log I can actually read back.

The eval itself is an LLM-as-judge panel that has to unanimously agree across three lenses: charge (is it actually charged enough), explicit guard (did it go too far), and coherence (is the Portuguese even readable). The panel has only gotten stricter over time, on purpose, so a lower score later doesn't mean the model regressed. It means the bar moved.

the honest number

Best result logged so far is 17.6%: the model clears that strict three-judge panel on 17.6% of held-out test cases. The run that produced it hit a session limit partway through eval, and every call that never completed auto-counted as a fail, so the real number is probably higher. I'm reporting the floor anyway.

The move from 1.5B to 3B wasn't in the original plan. The 1.5B base kept garbling Portuguese under LoRA, and the 3B base held together once the LoRA scale came down from MLX's default of 20 to 2, which the fine-tuning-expert skill flagged as too aggressive for a task this narrow. Coherence is fixed now. What's still failing is charge: the model plays it safe and mostly echoes the input back with barely a shift, which is the opposite failure of a joke that's too explicit but just as much of a miss.

why I'm shipping this before it works

Every other project on this site is either live or clearly finished. This one isn't, and I think that's worth showing too. The interesting part was never going to be the final accuracy number. It's that an agent curates the data, another runs the research loop, and I spend my time reading ledgers and deciding what to try next instead of writing training scripts by hand. The model still doesn't get the joke. The pipeline that's trying to teach it does most of the work on its own, and I'm not done pushing on it.

Source and the full ledger are on github.com/leonardo-meireles/laeleficator.
